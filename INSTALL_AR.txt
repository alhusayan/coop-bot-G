Findzia — SearchApi أساسي وSerpApi احتياطي
الإصدار: v128.5.42.42-searchapi-primary
الحالة: جاهز للتركيب، اختُبر محلياً. لم يُرفع إلى GitHub أو Railway.

التركيب
1. في المجلد الرئيسي لمستودع alhusayan/coop-bot-G:
   - استبدل main.py بالملف المرفق.
   - أضف findzia_searchapi.py بجانبه.
   ارفع الملفين معاً في تعديل واحد، خارج مجلد frontend.
2. مفاتيح SEARCHAPI_API_KEY وSERPAPI_API_KEY يجب أن تبقى في خدمة API على Railway.
   لا تضع المفاتيح في الكود. لا تحتاج حذف مفتاح Serper القديم.
3. ينشط التوجيه الجديد تلقائياً عند توفر المفتاحين بعد نشر خدمة API.
   القيم الافتراضية:
   SEARCHAPI_PRIMARY_ENABLED=true
   SEARCHAPI_FALLBACK_AFTER_SECONDS=6
   SEARCHAPI_TOTAL_TIMEOUT_SECONDS=18
4. بعد نشر خدمة API، ابحث في السجل عن:
   SEARCH PROVIDER POLICY primary=searchapi ... lens=searchapi
   وتأكد أن إصدار API أصبح v128.5.42.42-searchapi-primary.
5. جرّب بحثاً نصياً وصورة، وتحقق من المنتجات المحلية والأسعار والصور.

السلوك
- Google Lens وGoogle Search وGoogle Images وGoogle Shopping، ومسار Baidu الموجود، تبدأ عبر SearchApi.
- خطأ HTTP أو اتصال أو رد غير صالح يحوّل إلى SerpApi مباشرة، مرة واحدة لكل طلب نقل منطقي.
- حد انتظار الأساسي 6 ثوانٍ. للمهام المساعدة ذات المهلة الأقصر يبدأ الاحتياطي أبكر.
- مهلة النقل الإجمالية لا تتجاوز 18 ثانية، وتلتزم بالمهل الأقصر التي يرسلها المسار الحالي.
  هذا حد النقل فقط، وليس وعداً بظهور بطاقات Findzia خلال 6 أو 18 ثانية.
- عند تكرر فشل SearchApi يتجاوزه التطبيق مؤقتاً، ثم يجربه مجدداً.
- نتيجة فارغة صريحة لا تُعد سقوطاً للمزود ولا تُطلق طلباً مدفوعاً آخر وحدها.
- مشاركة الطلبات المتطابقة والكاش تقللان التكرار. لا تعرض الإجابة المتأخرة بعد انتهاء الطلب.
- أوقفنا مسار Bing/Brave الموازي القديم أثناء تفعيل هذه السياسة؛ لا يبدأ SerpApi كطلب موازٍ له.
- طلبات تفاصيل Google التي تحمل رموزاً خاصة بـSerpApi تبقى لديه؛ لا تُرسل رموزه إلى SearchApi.
- فحص هوية المنتج والسعر والصورة والعملات، والبلدان واللغات، وفوترة رصيد المستخدم تبقى في المسارات الحالية.
- لا يوجد تعديل للواجهة أو الدفع أو قاعدة بيانات الحسابات.

ملاحظات مهمة
- إعدادات JSON للمزودين ليست متطابقة؛ الوحدة الجديدة تحول الصور والسعر والعملة والمتجر والترقيم.
- SearchApi لا يقدم خيار auto_crop نفسه الخاص بـSerpApi؛ نرسل صورة المرجع كما هي.
- وحدات النص الداخلية ما زالت تحمل أسماء serper_* حفاظاً على سلوك المعالجة الحالي،
  لكن لا ترسل طلباً إلى Serper عند تفعيل السياسة؛ search_metadata.provider يحدد المزود الحقيقي.
- قد يحتسب المزود الأساسي طلباً انتهى لدينا بمهلة إذا أكمله عنده؛ لا يمكن ضمان عدم احتساب طلبين
  لدى المزودين عند التحويل. هذا لا يخص خصم رصيد المستخدم داخل Findzia.
- جميع التجارب لهذه النسخة محلية ومحاكاة. اختبار الصور الحي السابق أثبت الاتصال فقط،
  ولا يغني عن فحص النسخة بعد التركيب أو اختبار فترة الزحمة.

الرجوع الفوري
اضبط SEARCHAPI_PRIMARY_ENABLED=false ثم أعد نشر خدمة API.
يعود مسار المزودين السابق وفق متغيراته السابقة، وتبقى الملفات الجديدة قابلة للإزالة لاحقاً.
